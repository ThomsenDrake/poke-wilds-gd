# Reliability

## Local gate (verify_all)

The one-command pre-push ritual is `python3 tools/verify_all.py` (Workstream L.1). It ORCHESTRATES the existing verification tools via subprocess — it never forks their logic, never changes an orchestrated tool's behavior or exit-code contract, and is stdlib-only (a core tool; the only thing it `importlib`-loads is `tools/vision_review.py`, itself stdlib-only, for `review_is_fresh`; it never imports `vision_metrics`). It runs every step and reports the FULL picture (run-all by default, not fast-fail), cheap static gates first so their failures surface at the top, refusals last because they certify the artifacts the steps produced. It is a LOCAL ritual: CI stays lint/contract-only and the legibility-garden stays a separate docs-only workflow — `verify_all` changes neither.

```bash
python3 tools/verify_all.py [--skip-windowed] [--timeout N] [--windowed-timeout N] \
  [--json PATH] [--godot-bin PATH] [--base REF] [--fail-fast] [--quiet]
```

| Flag | Meaning |
| --- | --- |
| `--skip-windowed` | Display-less environments. Skips the windowed pixel lanes (S8/S9), suppresses refusals R3/R4/R5, and degrades R6 to a WARN (R6 always runs — it is never suppressed); those lanes are reported SKIP (reason "windowed lane skipped (--skip-windowed)"), NEVER PASS, and the result records `skip_windowed=true`. R1/R2 still apply to the headless report. This is the honest headless path — see below. |
| `--timeout N` | Per-scenario wall-clock budget passed to `run_playtests --timeout` for the headless suite (default 120). |
| `--windowed-timeout N` | Per-scenario budget for the two windowed lanes (default 600, matching the documented 600000 ms windowed bound). |
| `--json PATH` | Machine-readable result; default `.godot-smoke/verify_all.json` (gitignored). |
| `--godot-bin PATH` | Passthrough to `run_playtests --godot-bin` (default `GODOT_BIN` env else `/Applications/Godot.app/Contents/MacOS/Godot`). |
| `--base REF` | Optional passthrough to `check_change_contract.py --base` (default none ⇒ diffs working tree + untracked vs HEAD). |
| `--fail-fast` | Abort at the first nonzero step (default is run-all). |
| `--quiet` | Suppress echoing each tool's stdout; still print the per-step status line + timing, and on failure the captured output tail. |

### Refusals (R1–R6) — mechanical, not policy

The refuse-on-mismatch and freshness rules that were "human/agent-enforced policy until verify_all" are now MECHANIZED. Each refusal is a loud line on stdout plus a `refusals[]` entry in the result file; none is ever a silent pass. Since the agent-surface completion sprint every `refusals[]` entry ALSO carries the error-as-directive envelope fields `code`/`retryable`/`hint` (the same `{code, retryable, hint}` triple the per-scenario results carry, single-sourced via `error_envelope` in `tools/godot_dap_smoketest.py`; null on ok rows and on envelope-less tool_errors), so an agent matches a stable machine code instead of parsing prose. The per-scenario code set + retryable semantics are enumerated in `docs/references/agent-integration.md` § Error-as-directive; the load-bearing rule: every ok-flipping post-step gate (region diff, sidecar seeds, contrast, anchors, soak tripwire, vision review) sets its OWN envelope at the flip site, deterministic pixel/seed/pin reds carry `retryable: false` (a plain re-run cannot pass — the hint names the exact gate artifact/command), and `exceptions_captured` names script errors/timeouts only (a deterministic gate red never masquerades as a retryable flake). The line's shape follows the entry's `level`: a `refusal`-level entry prints `[REFUSE] <message>` (plus a `verify_all: <message>` line on stderr), a `tool_error`-level entry prints `[TOOL_ERROR] <message>` (also with a stderr line), and a `warn`-level entry prints `[WARN] <message>` on stdout ONLY (no stderr line). R3–R5 run only when NOT `--skip-windowed`; R6 always runs but degrades to a WARN there.

- **R1 — report head_sha == git HEAD** (envelope code `stale_head_sha`, retryable). Every generated report (playtest-report.json, verify-visual_sweep.json, verify-ui_render_audit.json) must carry `report["head_sha"] == HEAD` (HEAD sampled once via `git rev-parse HEAD`). A stale report is never certified.
- **R2 — report shape / stamp-key presence** (envelope code `report_invalid`, retryable). Each report must be a JSON dict carrying `head_sha`, `godot_version`, `window`, `renderer` (nulls allowed for the headless report).
- **R3 — windowed stamps vs environment (verify-visual_sweep.json only)** (envelope code `stamp_mismatch`, NOT retryable — the baselines must be regenerated under the current binary/renderer/window first; the hint names the `visual_sweep_update` regeneration command). `window` must == canonical `[1152, 648]` AND the baseline sidecar `window`; `godot_version` must be non-null AND exactly == a committed baseline sidecar `capture_env.godot_version` ("4.6.1-stable (official)", engine-stamped, no normalization), with a leading X.Y.Z triple cross-check against `Godot --version` (a regex extracts the leading triple — `4.6.1` from the CLI's `4.6.1.stable.official.<sha>` — and the report's `godot_version` must start with it; never an exact-string equality, since the stamp carries the engine suffix); `renderer` must be non-null AND == the baseline sidecar `capture_env.renderer` (read from `09_battle.png.sidecar.json`, not hardcoded — `project.godot` does not pin the renderer, so the engine-resolved value the capture stamped is authoritative; stays portable to `d3d12` on Windows). A sweep captured under a different binary/renderer/window is refused rather than diffed.
- **R4 — windowed entries present** (envelope code `windowed_lane_missing`, retryable). verify-visual_sweep.json must contain a `visual_sweep` entry with `transport == "windowed"` (not "skipped-headless" — guards against `PLAYTEST_FORCE_HEADLESS` leaking in); verify-ui_render_audit.json must contain a `ui_render_audit` entry.
- **R5 — ui_render_audit transport gate** (envelope code `dap_endpoint_unreachable`, retryable). The `ui_render_audit` entry's transport must be in {`dap`, `windowed`}. If it is `headless` (editor/DAP down → the runner fell back → the graduated red-tier pixel half never ran), that is a silent-pass hazard ⇒ REFUSE.
- **R6 — vision-review freshness** (envelope code `vision_review_stale`, retryable). `vision_review.review_is_fresh(doc, .godot-smoke/shots, docs/generated/visual-baselines)` (importlib-loaded; `baseline_dir` passed so all four recorded hashes gate) over the just-regenerated `.godot-smoke/vision-review.json` must be true.

### Exit codes (single process exit = most severe class present)

- **0 GREEN** — every step passed and no exit-escalating refusal fired. `refusal`- and `tool_error`-level refusals always escalate (to 2 or 3); a `warn`-level refusal (R6's `--skip-windowed` degradation) NEVER does — it is recorded (`refusals[]` with `level="warn"`, counted in the result's `summary.warnings`) and printed (a `[WARN]` line, plus the `WARN: N` column in the summary line) but leaves the exit code at 0, since a deliberately-skipped lane can neither certify nor block. So a `--skip-windowed` run can exit 0 while carrying an `ok=false`, `level="warn"` `refusals[]` entry — that is the documented honest skip, NOT an unclean run; do not misread it as a certification failure.
- **1 STEP_FAILURE** — a trustworthy run that found real defects: a static gate returned 1, determinism pins/canary returned 1, or run_playtests returned 1 (a scenario failed / a region or audit red-tier). Legibility is generate-only, so it never produces a 1. A transport-skip is NOT a 1.
- **2 REFUSAL** — verify_all will NOT certify the run (loud, nonzero, never a silent pass): report head_sha ≠ HEAD, a report missing stamp keys / not a dict, a windowed stamp mismatch vs environment, a windowed entry absent or wrong transport, ui_render_audit ran headless, or vision-review.json stale.
- **3 TOOL_ERROR** — a step could not run correctly: determinism exit 2 (usage/decode error), run_playtests exit 2 (Godot binary missing), a subprocess failed to launch or exceeded its outer hang-backstop (windowed: after the one occlusion-stall retry), or a report/JSON verify_all must read is absent/unreadable/corrupt. No valid result was obtained.

PRECEDENCE: TOOL_ERROR(3) > REFUSAL(2) > STEP_FAILURE(1) > GREEN(0). A tool-error means no valid result (dominates); a refusal means a result exists but cannot be certified (dominates a plain defect); a step-failure is a certified run that found defects. The full detail — every step + every refusal — is always in stdout and the result file regardless of which single code is returned, so collapsing to one code never hides information.

### `--skip-windowed` (display-less path)

For environments with no GUI (SSH, a display-less runner). It skips S8/S9, suppresses R3–R5, and degrades R6 to a WARN (R6 always runs — never suppressed); the windowed lanes are reported SKIP, never PASS, and the result records `skip_windowed=true`. R1/R2 still certify the headless report. It is an honest acknowledgment that the pixel lanes did not run — NOT a green for them. The degraded R6 warn entry is recorded (`refusals[]` `level="warn"`, `summary.warnings`) and printed (`[WARN]` line, `WARN: N` in the summary) but never escalates the exit code (see the GREEN bullet above): a `--skip-windowed` run that exits 0 with a single `ok=false` warn entry is a clean, honestly-degraded run, not an unclean one. `verify_all` itself stays a LOCAL ritual even on this path; no CI workflow is involved.

### Result file

Default `.godot-smoke/verify_all.json` (gitignored — `.gitignore` ignores all of `.godot-smoke/`; never tracked-file churn; schema `verify-all/1`). It records `head_sha` (sampled once at start), `generated_at` (UTC), `cwd`, `skip_windowed`, `godot_bin`, `duration_s`, the process `exit_code`, one entry per step, a `stamps` comparison table (git_head vs each report's head_sha; godot_version vs baseline capture_env + binary triple; window vs canonical + baseline; renderer vs baseline capture_env; vision_review_fresh), a `refusals[]` array, and a `summary` of counts (`passed`, `failed`, `skipped`, `refusals`, `warnings`, `tool_errors` — `warnings` counts warn-level refusals only and never affects the exit code; `tool_errors` merges step tool_errors with tool_error-level refusals, exactly matching the printed summary line's `PASS`/`FAIL`/`SKIP`/`REFUSE`/`WARN`/`TOOL_ERROR` columns). Every step entry carries `name`, `kind`, `argv`, `status` ∈ {pass, fail, skip, tool_error}, and `duration_s`; entries that ran a tool additionally carry `output_tail` (≈ last 40 lines — self-describing for a later agent) and `exit_code` (the tool's code once it returned one; `null` for a timeout/launch-failure tool_error). SKIP entries (a windowed lane under `--skip-windowed` or a missing binary) instead carry a `skip_reason` and have no `exit_code`/`output_tail`. Conditional fields appear per step: `env` only when a step overrides the child env, plus step-specific extras (`error`, an `issues` count on a failing `count_issues` gate, the determinism `json`, each windowed step's `report` path, the legibility `total_findings`). Each `refusals[]` entry is `{check, ok, detail, level, code, retryable, hint}` with `level` ∈ {refusal, tool_error, warn} (R6's `--skip-windowed` degradation is the `warn` case); the `code`/`retryable`/`hint` envelope triple is populated on every coded not-ok row (the R1–R6 codes above) and null on ok rows and envelope-less tool_errors. The canonical `.godot-smoke/playtest-report.json` remains the honest headless full-suite result (stamps null); the two windowed reports live beside it under distinct names.

### Honesty notes

- A transport skip (headless `visual_sweep`) is NEVER a failure — it is `ok=true`/SKIP and does not contribute to exit 1.
- A missing/stale report or a stamp mismatch is a REFUSAL (exit 2), never a silent 0; a missing Godot binary is TOOL_ERROR (exit 3), never a silent pass. A missing binary is detected once and the dependent windowed steps are marked SKIPPED(binary-missing) rather than each re-erroring.
- S4 (`check_change_contract.py`) diffs the working tree + untracked vs HEAD, so running `verify_all` mid-development with uncommitted `.gd`/`.tscn` but without the co-modified docs fires (exit 1). That is the change contract working as intended, not a runtime-gate defect; use `--base REF` to scope it.
- Expected wall time on this machine is ~1–2 minutes (measured ~63s for a full green run; the headless full suite ~50s and the windowed visual_sweep are the long poles); a slower run is not a hang — each lane is bounded by its per-scenario timeout and the outer backstop (an occlusion-stall retry can add one windowed lane budget).

## Automated playtests

```bash
python3 tools/run_playtests.py                    # journey, soak, and all four audits
python3 tools/run_playtests.py --include-smoke    # everything plus smoke scenarios and visual_sweep
```

`playtest_journey` scripts a full player loop (fresh game, overworld steps, a battle played to completion, menu navigation, save round-trip). `playtest_soak` runs a seeded bot (~150 iterations of walking, battles, menu cycles, saves) asserting HP/PP/bag invariants every iteration. `playtest_field_soak` (Phase 4) runs the same seeded bot under the `FIELD_MOVES_PARTY` fixture with an added field-move action band (`playtest_bot.try_random_field_move` — repel/flash/teleport/fly/ride driven off the seeded rng with inline postcondition asserts, degrading to a walk when no capable move rolls) so the soak exercises the field-move loops at depth; it is self-guarded (backup/restore save) and kept SEPARATE from `playtest_soak` so the fresh-game starter-party invariants stay untouched (Workstream L.6). `nav_audit` proves traversal agreement (blocked/walkable tiles, field-move gates) and battle/menu navigation reachability with model/cursor consistency; its battle half pins BOTH runtime rngs via `game_runtime.seed_for_smoke(NAV_AUDIT_SEED)` (the house seeding convention) so the wild draw and battle rolls are a pure function of (code, save, seed) — the pass event is never gated on per-process wall-clock-seeded RNG (miss-002) — and its RUN check is TOTAL: a legitimate "Can't escape!" trap refusal is proven, the trap expired, and escape re-proven, never recorded as a suite failure. `texture_audit` loads every battle sprite and overworld tile texture through the real pipelines (frame shape, keying). `data_audit` proves encounter-pool battle viability, instance integrity across levels, and bag/catalog resolution. `layout_audit` proves worst-case label fit and cursor alignment across battle and menu screens. Every scenario — smoke or playtest — backs up the player's save file before running and restores it afterward. The runner uses the editor DAP endpoint when available and falls back to headless Godot otherwise; it writes `.godot-smoke/playtest-report.json` and exits nonzero on any failure. Warnings are reported, not failed; exceptions and missing events fail.

Total-run reporting contract (miss-002): every scenario's red names its cause. Trace events ending in `_failed` are collected by BOTH transports as named failures (`failed_events` on the result, symmetric with the `_passed` payload special-casing), and `push_error`'s "ERROR: " line is captured as an exception (`ERROR_MARKERS` single-sourced in `tools/godot_dap_smoketest.py`, imported by `tools/run_playtests.py` so the transports agree by construction) — a red can never surface again as a blank "missing required events" with `exceptions: []`. A scenario can never end silently: the non-pass branch emits a `<scenario>_failed` trace carrying its reasons alongside `push_error` (`nav_audit_failed` is the going-forward contract). Handled engine-side refusals stay quiet at the source (e.g. `save_store.gd` parses corrupt saves via `JSON.new().parse`, which returns an error code without the engine printing "ERROR: Parse JSON failed"), so the widened capture adds no false reds on green paths. Since the agent-surface completion sprint every red result ALSO carries a structured error envelope on its `error` key (`{code, retryable, hint}`, null on green; single-sourced via `error_envelope` in `tools/godot_dap_smoketest.py` so both harnesses and `verify_all` classify identically — the error-as-directive convention made real): `dap_endpoint_unreachable` (the editor's DAP endpoint is down; the hint names `PLAYTEST_FORCE_HEADLESS=1` for harnesses with a headless fallback), `exceptions_captured` (a captured script error/timeout — the most upstream cause — outranks), `scenario_failed` (a `<scenario>_failed` trace carries its reasons; NOT retryable as-is), `missing_required_events`, and the Lane-4 trio `vision_review_failed`/`vision_review_stale`/`vision_review_incomplete`. Every ok-flipping post-step gate (region diff, sidecar seeds, contrast, art anchors, soak tripwire) sets its OWN envelope at the flip site — `region_gate_failed`, `sidecar_seed_mismatch`, `contrast_failed`, `anchor_refused` / `anchor_drift_failed`, `soak_tripwire` — so a red can never be envelope-less.

### Legibility oracles (Slice 4)

Three coded legibility checks sit on top of the capture contract (full contract + measured evidence: [product-specs/vision-fidelity.md](product-specs/vision-fidelity.md) § Legibility oracles):

- **Glyph template oracle** (`scripts/app/text_oracle.gd`, in-engine): called by `ui_render_audit`'s pixel half per battle state — windowed only (headless `_pixel_half` returns early, so the oracle never runs without a real renderer). It rasterizes each expected string (fonts.ttf@7, black-on-white) in a throwaway SubViewport parked on the audit node, reads the ink mask back after `frame_post_draw`, and XOR-matches it per glyph against the engine readback with budgets calibrated from measured noise: `T_str = 2` px/string and `T_glyph = 1` px/glyph (measured equivalence gap 0, cross-launch 0, white-vs-#f8 fringe ≤1 px/string — 2x headroom over the worst measured fringe). There is no standalone CLI; exercise it via `python3 tools/run_playtests.py --scenario ui_render_audit` (windowed; bind the run with a 600000 ms timeout, never run windowed scenarios concurrently).
- **WCAG contrast** (`tools/contrast_check.py`, stdlib): linearized-sRGB relative-luminance ratio over a label rect (fg = median of sorted distinct ink colors, bg = median of sorted distinct fill colors — conservative by construction), AA threshold 4.5:1 for the 7px battle text. Pure function of pixels: sort distinct colors, take the median of the sorted list — no RNG, no float-ordering nondeterminism, so identical input bytes ⇒ identical ratios. Determinism proof (3 runs, zero variance): run `python3 tools/run_playtests.py --scenario visual_sweep` three consecutive times windowed — Slice 2 proved those captures byte-identical (2/2 bit-identical sweeps, max drift 0.0) — and point the check at each run's shot PNGs + sidecar `labels[].display_rect`; the three ratio vectors must be identical. It is also trivially constant on the committed baselines, which `python3 tools/generate_legibility_report.py --output .godot-smoke/legibility-report.md` exercises in its Contrast section with no Godot. Findings file as quarantine kind `contrast_low` (report-tier via the `visual_sweep` runner post-step; coded RED only after the determinism proof + a clean-run history).
- **CVD simulation** (`tools/cvd_sim.py`, stdlib): Machado, Oliveira & Fernandes 2009 severity-1.0 matrices (IEEE TVCG 15(6), DOI 10.1109/TVCG.2009.113; values from Machado's 2010 thesis, LUME handle 10183/26950; import-time row-sums-to-1.0 assert as a white-preservation + tamper check) simulate the HP-bar triple (#3aa63f / #edba1e / #d03d34) and the sidecar `palettes.canary` under protan/deutan/tritan. Palette-based, so identical on fresh vs committed sidecars — the legibility report's Color-vision deficiency section is the sufficient invocation. Findings file as `cvd_collapse`: QUARANTINE FOREVER — accessibility evidence, never red, never flipped by any clean-run streak.

Recalibration protocol (mandatory after ANY `project.godot` rendering pin, font `.import` parameter, or Godot binary change): re-run the two-launch raster XOR (two separate sequential windowed launches rasterizing the 17 battle strings at 7px, XOR-compared via the repo's stdlib PNG decoder) and re-run the 3-run contrast proof; if the measured noise N rises, raise T from the new N — never hardcode. Refuse to compare calibrations across `godot_version`/`renderer` stamps (the 7px raster is driver/binary-specific: MoltenVK/Vulkan here vs `d3d12` on Windows); the Slice 1 report stamps record which stamp the calibration was measured under.

Graduation procedure (per battle state, Slice 6 rule): record consecutive clean windowed `ui_render_audit` runs with zero `glyph_mismatch` and zero garble/low_ink in the state's rects, plus glyph-oracle agreement; at 5 clean runs flip that state's `GRADUATED_STATES` key to true in `scripts/app/ui_render_audit.gd` and record the evidence — the clean-run entries in the graduation ledger (the recorded-evidence binder documented in the next paragraph), the measurement table and tolerance rule in [product-specs/vision-fidelity.md](product-specs/vision-fidelity.md). Order: `battle_moves` + `battle_item` first (anchor-mode strings — the model fully specifies the integer pen, so the 0-gap proof applies directly), `battle_action` on lint cleanliness (its FIGHT/PKMN/ITEM/RUN strings are baked art, not glyph-matched), `battle_message` last (box-mode — always carries a 1px placement fringe). Menu/party/bag/storage states must NEVER be added to the dict: the GBC restyle wave 2 moved their text onto fonts.ttf@7 inside the 160×144 stages, but `_audit_menus` still has NO pixel half (the scene-tree half measures them as ink-rect text extents against `stage_root()` bounds, skipping deliberate `clip_text` rows), so there is no pixel lint to graduate — the glyph-equivalence raster policy applies to the battle states only. Graduation evidence is valid only at the canonical 1152x648 window (integer battle scale 4); a fractional-scale capture keeps the match quarantine-tier.

Graduation ledger & calibration (Slice 6): clean-run evidence is RECORDED, not asserted — `tools/graduation_ledger.py` (stdlib-only) maintains `docs/generated/graduation-ledger.json`, a TRACKED canonical-JSON (git-diffable) evidence binder whose streaks are COMPUTED from entries. It is a human/agent ritual, deliberately NOT a runner post-step: the ledger is a tracked artifact (a post-step would mutate a committed file on every run — git noise, accidental-commit hazard, unlike the gitignored report/quarantine fields), and `record` needs the machine-local `user://` trace-log join. Historical sessions carry no `head_sha` (single-slot reports, boot-clock `ts_msec`), so there is NO BACKFILL — a streak starts at the first stamped `record`; earlier sessions are citable as prose only. Ritual — sequential, bind each windowed run with a 600000 ms Bash timeout, commit the ledger with the flip:

```bash
python3 tools/run_playtests.py --scenario ui_render_audit && python3 tools/graduation_ledger.py record
python3 tools/graduation_ledger.py status       # read-only: streaks, FLIPPABLE declarations, blockers, next steps
python3 tools/graduation_ledger.py calibration  # once per legibility-garden cycle (weekly, Mon 14:00 UTC); commit the snapshot
```

`record` banks ONE run: it refuses a report without a `ui_render_audit` entry ("re-run first") and a report older than the ledger's last entry (single-slot join hazard), resolves the append-only `agent_trace.jsonl` (macOS `~/Library/Application Support/Godot/app_userdata/PokeWilds-Godot/logs/`; `--trace PATH` overrides for portability — CI has no user:// log), takes the LAST boot-delimited session containing audit events, cross-checks report↔session (both pass events agree with `events_seen`; `quarantined` equals the per-state finding sum; the `text_oracle_passed` payload shows states_checked=4, glyphs_checked>0, T_str=2/T_glyph=1 — any mismatch is an anomaly flag, and an anomaly-flagged entry is INELIGIBLE (untrusted evidence): like other missing-evidence ineligibles it NEITHER COUNTS NOR BREAKS a streak, UNLESS the report is ok=false, in which case it is a windowed RED that breaks every state), computes per-state clean, embeds counts + ≤8 sample payloads (self-sufficient if the JSONL is deleted), and dedupes on the session identity `(start_line, boot_ts_msec)`. A run is ELIGIBLE iff transport ∈ {windowed, dap} AND `ui_render_audit_passed` AND `text_oracle_passed` fired AND the report is ok; a state is CLEAN iff zero findings of kinds `glyph_mismatch`/`garble`/`low_ink`/`clipped`/`forbidden_ink`/`lint_unavailable` (`lint_unavailable` = missing evidence = dirty, never clean). MISSING-EVIDENCE ineligibles (headless CI, or a windowed run with ok=true that lacks a pass event) NEITHER COUNT NOR BREAK streaks, but an ineligible run with EVIDENCE OF A RED (windowed/dap with ok=false — the audit gate failed) BREAKS consecutiveness for every state (a failed windowed audit is not a clean windowed run); streaks reset on an eligible dirty entry and on a windowed red and `status` shows the reset reason (last dirty run id + kinds, with a windowed_red flag) plus stale-evidence detection (streak entries' `head_sha` ≠ current HEAD ⇒ both shas printed, 5 fresh runs needed — progress stays banked).

Flip procedure (when `status` prints FLIPPABLE — `battle_message` is the ONE exception and never prints FLIPPABLE by construction; see below): the trailing 5 eligible entries are clean AND fresh at `git rev-parse HEAD` (the flip is an uncommitted edit atop the evidence HEAD; ANY commit in between stales the streak), predecessor flips exist (`battle_moves`+`battle_item` before `battle_action`; `battle_action` before `battle_message`), then edit ONLY line 16 of `scripts/app/ui_render_audit.gd` (`false`→`true`, in-place constant edit, 0 added lines — the flip changes the verification harness's TIERING, not the game) and write the `flips[]` entry citing `evidence_run_ids` in the same tree. `battle_message` (box mode) is the deliberate exception to "only when FLIPPABLE": its DOCUMENTED box-mode judgment is a FIELD of the flip entry itself, so `status` cannot print FLIPPABLE for it beforehand — it prints DEFERRED (streak progress banked) until the flip records the judgment. It flips LAST, on its OWN fresh 5-clean streak, once the anchor (`battle_moves`+`battle_item`) and lint (`battle_action`) predecessors are in, writing the judgment (engine-owned ~1px pen offset, glyph match excluded by design, lint cleanliness accepted as sufficient, deferral considered) into the `flips[]` entry in the same tree — after which `status` prints GRADUATED, never FLIPPABLE. That edit is app_bootstrap code ⇒ the change contract fires (registry + bootstrap-and-overworld.md + QUALITY_SCORE.md + RELIABILITY.md co-modified). Post-flip proof (perturbations temporary with git-diff revert proof): a seeded defect in the graduated state (the Slice-4 +1px ANCHOR-region shift in `ui_render_model.gd`, which keeps `_check_strings` passing at POS_TOLERANCE 1.5 while breaking the XOR ≫T_str) fails the scenario RED through the graduated gate with no per-bug assertion; the same defect class in a non-graduated state stays quarantine (`_failures` empty); a clean run stays green; `ui_render_model.gd` ends byte-identical to HEAD.

Calibration is free: the existing quarantine→graduation pipeline IS the loop — every pixel finding emits a `quarantine_finding` trace FIRST, and a graduated-state red leaves the same joinable record, so no new engine events. `calibration` (local-only: it needs the machine-local data) appends/replaces a cycle snapshot over runs since the last one: PRECISION = confirmed-true quarantine findings ÷ total in the window (a finding is CONFIRMED iff a later recorded run with the state graduated carries a same-defect-family finding overlapping its stage-px region — `visual_explain.rects_overlap`, the single geometry home; Lane-4 `vision_review` corroboration joins via `finding_id` + shot→state compatibility at the entry's recorded window, counted as corroboration, never as confirmation — Lane 4 never self-confirms), RECALL = graduated-gate catches ÷ real defects (graduated reds ∪ confirmed ∪ recorded seeded-proof plants). Zero denominators are honest: a null rate renders literally as `undefined (N of M — reason)`, NEVER 0.0/1.0/n/a-without-counts. Cycle 1 is the BASELINE; a two-cycle TREND needs the next legibility-garden cycle and is never claimed from one cycle. The garden workflow only RENDERS the committed snapshot — `tools/generate_legibility_report.py`'s "Graduation & calibration" section (absent ledger ⇒ "not yet recorded" note, never an error; calibration rows never count as findings, preserving the first `- Total findings: N` line the Legibility Debt issue regex matches).

Optional vision extra (Slice 6, opt-in): `tools/vision_metrics.py` is an SSIM-map corroboration pass over baseline|fresh shot pairs — advisory localization heat, QUARANTINE-TIER FOREVER, never a gate (full spec: [product-specs/vision-fidelity.md](product-specs/vision-fidelity.md) § Optional vision extra). Install the extra with `uv sync --extra vision` (or `pip install scikit-image` — pyproject `[project.optional-dependencies] vision = ["scikit-image>=0.22"]`); the core tooling stays dependency-free and plain `python3 tools/...` keeps working for everyone else. Standalone: `python3 tools/vision_metrics.py --shots-dir .godot-smoke/shots --baseline-dir docs/generated/visual-baselines --out .godot-smoke/vision-metrics.json` writes schema `vision-metrics/1` (per-16px-window `ssim_divergence` corroboration findings below an advisory 0.85 mean-SSIM floor). It is NOT a runner post-step and nothing it emits flips a result: SSIM windowing averages over 8-16px windows, which dilutes exactly the sprite-scale (1-frame strip offset) and glyph-scale (1-2px XOR) defects the coded oracles catch at exact pixels. Without scikit-image installed the tool prints a skipped note and exits 0, and the legibility report's SSIM section renders a skip note. It is the ONE tool exempted from the core stdlib-only guard (`OPTIONAL_TOOL_EXEMPTIONS` in `tools/check_repo_contracts.py`, which also hardens against any core tool STATICALLY importing it — an AST-level source check that flags a core tool's `import vision_metrics`; a runtime `importlib` load of the file is out of scope for that static guard).

## Agent vision review (Lane 4)

`tools/vision_review.py` runs after EVERY windowed visual-sweep family capture — as a `run_playtests.py` post-step (`apply_vision_review`, after `apply_region_gate` and `apply_contrast_cvd`) and standalone. The windowed acceptance path invokes `tools/vlm_reviewer.py` by default and requires a fresh model pass for every covered shot, including unchanged shots. It writes `.godot-smoke/vision-review.json` (schema `vision-review/2`; rubric, grounding contract, region-id namespace, and finding schema in [references/vision-review-rubric.md](references/vision-review-rubric.md); full spec in [product-specs/vision-fidelity.md](product-specs/vision-fidelity.md) § Lane 4 automation):

```bash
python3 tools/vision_review.py --shots-dir .godot-smoke/shots --baseline-dir docs/generated/visual-baselines
```

SUPPORTING REVIEWER — a deterministic in-process sidecar-consistency checker remains composite and CI-safe (byte-stable findings per seed), but it cannot satisfy the required windowed acceptance path without a model pass. It diffs fresh vs committed baseline sidecars (labels deleted/moved/text-changed, cursors missing/moved/appeared, draw-order changes, canary palette drops, canary/expected-region deltas) and reports unexplained change clusters from the region diff — every finding cites a sidecar region id and intersects its bbox BY CONSTRUCTION. It emits nothing for byte-identical shots and nothing groundable for overworld/menu shots lacking sidecar regions (the coverage gap is counted, not faked).

PLUGIN CONTRACT — `--reviewer-cmd "cmd args"` (split via `shlex.split`, never `shell=True`): the command receives per-shot stdin JSON `{shot, shot_kind, paths{before, after, som_before, som_after, crops[], expected_strings, rubric, context}, reviewer_params, finding_schema, region_table, window, clusters, som_legend, grounding_rules}` and must print `{"findings": [...]}` to stdout within the hard timeout (default 300s). `window` (the shot's `[w, h]` frame bounds), `clusters` (its change regions), and `som_legend` (the SoM number→region_id join) are carried in stdin — not only the on-disk `context.json` — so a plugin can construct in-frame, groundable bboxes from stdin alone. Non-zero exit, timeout, or invalid JSON is a TOOL ERROR — exit 2 standalone, red through the runner exception path (fail-closed like every other gate; a hung or garbage plugin is never a silent pass). Per-changed-shot evidence bundles (full-frame before/after byte copies, native-resolution cluster + region crops, numbered Set-of-Mark overlays per arXiv 2310.11441, the expected-strings manifest, the state-group rubric excerpt, context + region table) land in `.godot-smoke/vision-review/<stem>/`.

GROUNDING ENFORCEMENT — after ANY reviewer returns, the pipeline drops + counts every finding that does not cite a resolvable sidecar region id AND intersect one of its rects (`visual_explain.rects_overlap`, the single geometry home): 100% of emitted findings are grounded by construction, and a mock reviewer's ungrounded output is dropped and counted (in the file-level `grounding` stats) with exit still 0 — drops are not errors. Each emitted finding carries a `finding_id` (`vr1-<hex16>` — a stable hash of shot/class/region/values, identical across re-runs, transports, and reviewer implementations) that is recorded on every report quarantine entry of kind `vision_review` as the Slice-6 graduation-ledger join key.

WHEN IT RUNS — every windowed `visual_sweep` compare run, even with 0 changed shots (full manifest, zero findings), so any sweep whose shots change necessarily has a current file. The post-step is skipped under `PLAYTEST_FORCE_HEADLESS` transport and in update/auto_update mode, exactly like the region gate; if a transport-skip run leaves a stale file on disk, the runner REFUSES it — does not record `vision_review_written`, prints a warn (staleness is measured by the shot-hash manifest: sha256 of each covered shot's PNG bytes plus baseline + sidecar hashes — content hashes, mtime-independent). Refuse = ignore + warn + regenerate on the next compare run, NEVER red; only a vision_review tool ERROR (bad PNG decode, reviewer failure, unwritable output) fails red.

TIER — findings are QUARANTINE-FOREVER: recorded in the report quarantine section as kind `vision_review` (report-tier, never JSONL), never failing a run, unless a coded oracle independently confirms the same defect — in which case that oracle's failure governs, and Slice 6's graduation ledger joins the graduated finding to the quarantine `finding_id` it confirms. The gitignored output (`.godot-smoke/vision-review.json` + bundles) is deleted/overwritten unconditionally on first run — the stale July-2026 pilot's bare-array shape fails schema validation and is replaced, not repaired.

MODEL REVIEWER — headless Command Code `gpt-5.6-luna` first, hosted `qwen3.8-max-preview` second, local Ollama `qwen3-vl:8b` last (`tools/vlm_reviewer.py`, the G2 answerer): the Lane-4 `--reviewer-cmd` socket is PLUGGED IN and the runner now invokes it by default for every windowed sweep family. A successful acceptance manifest must show `model-vision-llm`, a completed bounded image review (Command Code uses one pass per image; network/local backends use the configured two-pass vote), and zero unanswered rubric questions for every covered shot; missing key/model, backend failure, timeout, malformed output, incomplete vote, or incomplete coverage fails closed with a secret-free reason. The first positive MODEL-ANSWERED manifest is LIVE-VERIFIED with headless Command Code `gpt-5.6-luna` (two passes, 5/5 battle answers); the same model capability covers all 27 rubric questions across all 7 shot groups. The model answers the rubric JUDGMENT questions and the non-baked-UI questions (overworld/menu/day-night) no coded class can express; it is NOT a geometric oracle (an 11px offset is the art-anchor layer's job — a VLM downscales to a pixel budget). `VISION_REVIEWER_CMD` may override the default command; standalone deterministic review remains available for maintenance:

```bash
# one-time (fits ~30GiB free; pin the explicit tag, never latest):
ollama pull qwen3-vl:8b
# runner post-step opt-in (the plugin always runs the deterministic pass too):
VISION_REVIEWER_CMD="python3 tools/vlm_reviewer.py" python3 tools/run_playtests.py --scenario visual_sweep
# or standalone:
python3 tools/vision_review.py --shots-dir .godot-smoke/shots --baseline-dir docs/generated/visual-baselines \
  --reviewer-cmd "python3 tools/vlm_reviewer.py"
```

`tools/vlm_reviewer.py` is pure stdlib (`urllib.request` + `json` + `base64`; NO SDK, NO venv) so it is a CORE tool — `OPTIONAL_TOOL_EXEMPTIONS` stays pinned to exactly `{vision_metrics.py}`. COMPOSITE: it ALWAYS runs the deterministic sidecar-consistency pass (importlib-loading `vision_review.default_reviewer`) and ADDS the model pass only when the model is POSITIVELY available; it declares what RAN via `reviewer_meta.kinds_ran` (the composite contract `vision_review._run_cmd_reviewer` folds into the rubric-coverage ledger's RAN set — the deterministic pass is always declared, the model kind only when it actually ran, so coverage is never faked by a degrade).

## Miss-postmortem protocol

When the suite misses a bug, fix the REASON it was missed at a SYSTEMIC level — never the specific miss (the governing directive, made mechanical). [references/miss-postmortem-protocol.md](references/miss-postmortem-protocol.md) prescribes the five required steps (fix+freeze the instance as the SUBJECT; NAME the missing anchor class — CO/HM/SA/XS/EA — and enumerate why every present check class was silent; ADD the class-level mechanism; PLANT a class-level regression and revert byte-identical; RECORD) and the tracked ledger [generated/miss-postmortems.json](generated/miss-postmortems.json) (schema `miss-postmortem/1`; refuse-on-unreadable; ritual-write, never a runner post-step; counts computed). A `check_repo_contracts` backstop (`miss_postmortem_issues`, folded into `run()`) resolves every recorded `mechanism_added` to a landed check (each named repo path exists; each named art-anchor id is in the registry) and every executed plant's `revert_proof` to its recorded `revert_scope` sha256 pins (position-independent — holds mid-slice and post-commit alike; a live `git status` would false-red on unrelated in-flight edits). A claimed-but-missing mechanism or a drifted/missing plant-scope file is RED; an incomplete entry (missing plant, silence-enumeration, or executed-without-scope) is advisory on stderr; a corrupt ledger is RED, never reset to empty. The HP-bar 11px escape is entry #1 — its class-level plant EXECUTED 2026-07-22 (windowed): first break silent at every RED tier with anchor_drift firing [quarantine] (and two quarantine-tier classes corroborating on the moved bar), regen-under-break REFUSED RED by `apply_anchor_gate` with all 48 prior baseline files restored byte-identical, revert sha-verified and the post-revert compare GREEN. Entry #2 (`miss-002-nav-audit-false-red`, 2026-07-22) is the protocol's first FALSE-RED variant (the suite intermittently lied, rather than missing a bug): nav_audit's required pass event was gated on per-process unseeded (wall-clock-seeded) rng — a trapping wild's legitimate "Can't escape!" refusal was recorded as a suite failure (~3-5% of fresh runs), and every scenario reported failure via `push_error` only, which the harness's old `ERROR_MARKERS` discarded, so the red surfaced REASONLESS ("missing required events" with `exceptions: []`). The mechanism is three coordinated landings — the `seed_for_smoke` determinism seam (`game_runtime.gd`) + the total trap-tolerant RUN contract (`nav_audit_battle.gd`) + the shared-harness `_failed`-event / `ERROR:`-capture reporting contract (`run_playtests.py` + `godot_dap_smoketest.py`) — whose two-part plant EXECUTED 2026-07-22 (headless): a forced turn-1 trap stayed GREEN and byte-identical across 20 fresh subprocesses (cold and warm) under the seed while removing the seed call diverged 10/10 event streams and restoring the pre-fix RUN check went 3/3 RED with the original failure text; and the pre-fix harness reproduced the reasonless red (`exceptions: []`) on the same forced failure that the fixed harness reports with its `nav_audit_failed` reasons — revert sha-verified byte-identical, the scope pinned by `revert_scope`.

## Current risks

- Smoke scenarios depend on a locally running Godot editor exposing DAP on `127.0.0.1:6006`.
- An empty species catalog now skips encounters with a `warning` trace instead of fabricating a synthetic mon; watch for that warning after touching `scripts/data/`.
- Battle mechanics follow the mainline formulas (type chart, stat stages, status, capture, growth curves); unsupported move effects degrade to plain hits and surface a `warning` trace with the effect id.
- Save schema v6 migrates v1-v5 payloads on load (v1/v2 drop the legacy `unlocked_field_moves` key; v3→v4 adds per-placement storage-box `contents`, absent = empty box; the infinite-world v5→v6 flatten drops the retired chain-identity keys — a chain-less save's delta is EXACTLY `{version: 6}`, `landmark_state` hoisted back to its top-level seat, legacy landmark/removal keys re-keyed per-instance); a TRULY CHAINED v5 save is structurally unrepresentable on the seamless plane and is refused non-destructively to `.chained.bak` (never a destructive flatten — see [product-specs/infinite-world.md](product-specs/infinite-world.md) § Save v6). The migration is covered by the dedicated `save_migration` fixture scenario (v1→v3, v2→v3, the v3→v4 contents round-trip + empty-backfill, the v5→v6 flatten + chained-refusal witnesses, plus the non-destructive refusal of a future version), in addition to `menu_save`, `field_move`, and `storage_flow`. Save writes are atomic (temp file + rename over the live save, so a crash mid-write leaves the previous save intact), and unreadable saves are recovered NON-DESTRUCTIVELY: a corrupt save is preserved to `.corrupt.bak` with a `save_recovery` trace, and a save newer than the supported version is refused with a `warning` and renamed to `.newer.bak` BEFORE the runtime starts fresh — so the per-step autosave can never overwrite a newer/unreadable save (the ordering is the whole point; reversing it would recreate the data-loss bug). The v4 bump is precisely what makes a v3 build refuse a box-contents save rather than loading semantics it has no UI for and autosaving over it.
- A storage box's contents live ON its placement entry (keyed by tile), so demolition removes entry + contents atomically and a NON-EMPTY box refuses Cut (`demolish_refused{box_not_empty}`) — a box can never be demolished with Pokemon inside (the no-loss half of the storage exit criterion), and deposit/party-release refuse to strand the party's last witnessed demolition move while structures stand (`would_strand_demolition` — the building spec's load-bearing witness invariant extended dynamically; box contents never count toward the party pool). See [product-specs/storage-and-party.md](product-specs/storage-and-party.md).
