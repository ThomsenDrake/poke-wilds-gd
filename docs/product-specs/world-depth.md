## Supported behavior

### Landmarks — a world-seed + chain parametric multi-tile footprint generator

- **The current world places ONLY single-tile props.** `biome_defs.gd:64-94`'s `_prop` shape is `{path, region, block, chance, reason, field_move, key_color}` — one tile + a chance, chosen by `_pick_prop` (`world_generator.gd:287-292`) beating the pure integer `_coord_noise(x, y, salt)` (:314-318). There is NO footprint/structure concept in world-gen; player structures (`structures.gd`) are one placement per tile under the shared 10k cap (`world_overrides.gd:21 MAX_OVERRIDES`). Phase 7 adds the FIRST multi-tile coherent structure, and it is DETERMINISTIC-FROM-SEED like props (reborn from noise, never saved as a mutation) — NOT a placement, so it never competes with the player's 10k cap and demolition's revert-to-cleared semantics never touch it.
- **The seam (frozen — chaining never rewrites it).** The landmark layer is consulted at the SINGLE mutation boundary (`world_generator.gd:109-114`, the one choke point where `_overrides` then `_placements` apply). A landmark tile is stamped into the base logic dict (`world_generator.gd:96-108`) BEFORE clears/placements apply, via a pure resolver the generator holds: `Landmarks.tile_logic_for(world_seed: int, chain: Vector2i, map_pos: Vector2i, base_logic: Dictionary) -> Dictionary` — returns `base_logic` UNCHANGED when `map_pos` is outside every footprint in that world; otherwise returns the landmark's per-tile logic (biome/`prop_path`/`walkable`/`block_reason`/`requires_field_move`/`encounter` + the NEW `landmark_id` and `encounter_token` keys, below). `Landmarks.landmarks_in_world(world_seed: int, chain: Vector2i) -> Array[Dictionary]` returns the deterministic landmark list a world hosts (each `{landmark_id, anchor: Vector2i, footprint: Rect2i}`); `Landmarks.anchor_for(world_seed, chain, landmark_id) -> Vector2i` derives the anchor by the `overworld_mons._mix` SplitMix convention (explicit sub-`INT64_MAX` constants + 63-bit masks, NO engine `hash()`, NO dict iteration). Because `chain` is a parameter the origin world fills with `Vector2i(0,0)`, the generator is chain-ready at birth — and Phase 7 REQUIRES it: `landmarks_in_world(seed, chain)` returns the full landmark set for ANY chain (§ Scope — DECIDED: chained worlds too, NOT a later data flip), each world anchoring its own instances from `(world_seed, chain)`, so chaining is served WITHOUT a generator change.
- **EVERY world hosts all three; origin hosting them on a fresh save is the pinned "destinations, not terrain" exit criterion.** Every world — origin AND chained — deterministically anchors the Mansion, the Ruins, and the Heart Tower from the same chain-parametric generator; presence is NOT seed- OR chain-gated (a world that rolled zero landmarks would fail the exit criterion). The origin guarantee is the destinations-exist guarantee: a fresh save starts in origin, so all three destinations exist from moment one; every chained world re-derives its OWN three from `(derived_seed, chain)`. The SEED + chain select only each anchor's tile + orientation within its biome ring. Anchors are searched outward from a seed-derived candidate at the landmark's target ring (§ Pinned constants) for a walkable region big enough for the footprint; the search is a pure function of `(world_seed, chain, landmark_id)`, bounded to `ANCHOR_SEARCH_BUDGET := 400` tiles (a landmark whose budget exhausts falls back to a fixed ring offset — never an absent landmark, never an unbounded loop; the FAQ's "world gen stuck >10 min" failure mode, `.firecrawl/fresh-faq.md:208-210`, is the bounded-generation contract this honors).
- **Footprint validation against props / structures / paths (frozen).** A footprint, when stamped: (a) OVERRIDES the scattered prop on every tile it covers (the landmark sprite replaces `_pick_prop`'s pick — coherence by construction, since the stamp wins over base logic); (b) sets `landmark_id` on every tile, and `Structures.can_place_on` (`structures.gd:227-235`, single-tile today) gains a `logic.get("landmark_id", "") == ""` clause so the player can NEVER build on OR demolish a landmark tile (faithful anchor: hard-stone structures need Smash to demolish, `pokewilds-build.md:46`, and statues are a buildable CATEGORY in the source wiki, `buildings-scrape.md:306` — the port keeps PLAYER statues buildable but landmarks are immutable world features); (c) walks the footprint's walkable interior through `reachable_walkable_count`'s hypothetical-`blocked` seam (`world_generator.gd:216-232`) at gen time so a landmark can never wall the player's spawn region (the build trap-guard reused as a footprint gate). Landmarks stamp at world-gen, BEFORE any player placement exists, so there is no landmark-vs-player-build collision to resolve at stamp time — the `can_place_on` clause is the lifelong guard.
- **Footprints are plane-abstracted (FLAGGED — the originals imply multi-floor interiors).** The `ruined_city/sewer/` subdir (Mansion basement/drainage) and the 251-tile `heart_tower/` set (a prototyped procedural tower) imply floors; the port is a 2D tile plane, so "floors" port as DISTINCT REGIONS of one footprint (Mansion: an outer ruin + a walled interior room grid + a `sewer` sub-region entered through a door tile; Ruins: `RUINS_OUTER` grounds + a walled `RUINS_INNER` chamber + an `underground` sub-region; Tower: a base chamber — § Heart Tower). #### Edge-cross triggers (faithful)

#### Adjacent-world generation from derived seeds (the determinism model)

- **Worlds form a 2D grid keyed by offset from origin** (the FAQ's "Surf/Fly back the same direction(s)" — coordinates are RELATIVE/directional). Chain coords `Vector2i(cx, cy)`; origin = `(0,0)`; crossing North from `(cx,cy)` enters `(cx, cy-1)` (screen-north = -y, the port's map convention). Each world is its OWN self-contained noise plane with its OWN local origin — rings, levels, nests, and legendary anchors all measure from the ACTIVE world's local `(0,0)`, so a chained world is a fresh disc, NOT a shifted view of one infinite plane (this is why chaining does NOT silently move every distance-gated system — each world re-derives from its local origin).
- **Per-world seed = pure hash of root + chain coords (NO new RandomNumberGenerator).** `WorldChain.world_seed_for(root_seed: int, chain: Vector2i) -> int`: for `chain == (0,0)` it returns `root_seed` ITSELF (so the origin world's terrain is EXACTLY the v4 world — § Save v5 byte-preservation); for any other chain it returns `_mix(root_seed, chain.x, chain.y, SALT_WORLD) & 0x7fffffff` (the `overworld_mons._mix` SplitMix shape — explicit constants + 63-bit masks, no engine `hash()`). `new_game` draws `root_seed = _rng.randi() & 0x7fffffff` (the existing `game_runtime.new_game:100` draw, renamed) and sets the active world_seed = `world_seed_for(root_seed, (0,0)) == root_seed`. On a cross, `world_chain_runtime` swaps the active world: it persists the outgoing world's mutations (maps + its `landmark_state`, written back through the frozen seam) into `chained_worlds` (§ Save v5), computes the new `world_seed`, calls `world_generator.setup(new_seed)` + re-applies that world's saved overrides/placements/campsite, RE-STAMPS the incoming world's stationary legendaries by re-running `LegendaryPlacement` for `(new_seed, chain)` suppressed by `legendary_removals` (legendaries are static entities, NOT sim entities — this explicit re-stamp is what keeps a chained world from shipping zero legendaries or stale origin ones; the `world_chain` scenario witnesses it), RE-APPLIES the incoming world's landmark puzzle state ALONGSIDE the re-stamp (`set_landmark_state(chain, chained_worlds[chain].landmark_state)` — absent → `{}`; the frozen seam is the only reader/writer `landmark_runtime` knows), repositions the player on the entry edge, and traces `world_chained {chain, world_seed, root_seed, method, newly_generated}`. **Reproducibility:** because every world's seed + content is a pure function of `(root_seed, chain)`, a chain `(0,0)→(0,-1)→(1,-1)` re-derives identically on every run; the ONLY per-world MUTATION state (player builds/clears, campsite, pastures, puzzle, removals) is what the save persists (§ Save v5). This pure-derive model is a DELIBERATE DIVERGENCE from the original's generate-once-persist-per-`map<x>,<y>`-file model (`fresh-faq.md:232-237`) — named in § Flagged divergences; the original persists first-entry generation, the port re-derives terrain from the root and persists ONLY player edits, which is strictly better for the determinism suite.
- **Crossing deposits the player on the entry edge (FLAGGED tile choice).** Crossing North deposits the player on the SOUTH edge of the new world (and symmetrically), on a seed-derived walkable beach/sand tile at distance `WORLD_RADIUS - 2` (`WorldChain.entry_tile_for(world_seed, from_direction)`), so the return crossing is immediately available; surf-crossing seeks a water-adjacent walkable tile. Bounded search, `ENTRY_TILE_BUDGET := 200`. The search walks BASE terrain (a resolver-less private generator — footprints never steer the deposit), so a deposit tile MAY sit under a landmark footprint once the incoming world's resolver re-stamps; the deposit is a WARP (never a stepped tile) and the opposite half-ring stays open, so the return crossing is never blocked (cosmetic, flagged).

The no-new-rng guarantee holds by construction regardless (the only root draw is the existing pinned `new_game` `randi`). The shared `_rng` (the wild-encounter stream, pinned by `seed_for_smoke` over `game_runtime._rng` + `battle_runtime._rng` + `player_avatar._rng`) is consumed ONLY where it already is — a landmark-scope encounter draws through the EXISTING `generate_wild_encounter` (same stream, narrower pool), and a legendary battle rides the Phase-6 forced-battle pending seam (the entity instance is stamped from the derived stream, never re-rolled).

- **Per-world seeds are a pure hash.** `WorldChain.world_seed_for(root_seed, chain)` is the `overworld_mons._mix` SplitMix shape (explicit sub-`INT64_MAX` constants + 63-bit masks, int64 multiply-wrap, NO engine `hash()`, NO dict iteration): `chain == (0,0)` → `root_seed` (origin terrain == the v4 world, byte-preservation); else `_mix(root_seed, chain.x, chain.y, SALT_WORLD) & 0x7fffffff`. `root_seed` is drawn ONCE at `new_game` from `_rng` (the only draw); every world thereafter is a pure function of it. So chains are reproducible: the same `root_seed` + the same crossing script yields the same chain of identical worlds.
- **Landmark/legendary anchors + puzzle are pure.** Anchors derive from `_mix(world_seed, landmark/species salt, chain)`; the Mansion statue toggle puzzle is input-driven (the player's interact order), so given a fixed `(root_seed, input script)` the entire world-depth timeline is fixed — exactly the Phase-6 step-indexed contract. Landmark encounter POOLS ride `filter_species_ids` (sorted ⇒ deterministic membership); the pool NARROWS to a token but the DRAW still consumes the shared `_rng` in the existing order, so a landmark walk perturbs the encounter stream EXACTLY as a same-length grass walk would (no NEW consumption pattern).
- **Cross-consumer continuity.** A world swap calls `world_generator.setup(new_seed)` (re-binds the three noise channels to the derived seed) but does NOT reseed `game_runtime._rng`/`battle_runtime._rng`/`player_avatar._rng` — the encounter trigger stream is continuous ACROSS worlds (crossing an edge does not reset the wild-battle sequence), so the six pinned double-run consumers and `rng_joint_pin` see no new perturbation beyond the player's own steps. `overworld_mons_sim.gd` reads `session.world_seed` directly for nest hashes — on a swap `session.world_seed` becomes the derived per-world seed, so nests/entities re-derive PER-WORLD automatically (distinct worlds, no code change to the sim). Legendaries are NOT sim entities (they are `LegendaryPlacement` statics rendered via `entity_layer`), so their per-world re-derivation is an EXPLICIT swap-contract step — re-run placement for the incoming `(world_seed, chain)` minus `legendary_removals` (§ World chaining) — NOT an automatic sim side-effect.
