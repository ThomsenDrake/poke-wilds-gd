## Warning-tier cases (specific `warning` events)

These are emitted through the existing `warning` event above; they are documented here so the structured payloads are discoverable.

- Save-version refusal — `trace.warning("SaveStore", "Save uses a newer schema; preserved it and starting fresh.", {found_version, supported_version, preserved_path})`. Fired when a save's `version` exceeds `SessionState.SAVE_VERSION`; the unreadable/newer file is renamed to `SAVE_PATH + ".newer.bak"` (reported as `preserved_path`) BEFORE the runtime starts a fresh game and autosaves, so the per-step autosave can never overwrite the preserved newer save. If the preserve rename fails, the refusal is a HARD STOP (`_live_path_protected`): the runtime does not fall through to a fresh-start overwrite of the still-live file.
- Unusable-save preservation — `trace.warning("GameRuntime", "Save parsed but could not be applied; preserved it and starting fresh.", {preserved_path})`. Fired when a version-OK payload fails `apply_loaded_state` (e.g. structurally unusable); the file is renamed to `SAVE_PATH + ".unusable.bak"` before the fresh start, so the parseable-but-unapplicable save is never clobbered either.
- Atomic-rename failure — `trace.warning("SaveStore", "Atomic save rename failed; the previous save is untouched.", {error})`. Fired when the temp-file→final atomic rename in `write_payload` fails; the previous save is left intact and the write returns false.
- Failed-preserve write refusal — `trace.warning("SaveStore", "Save write refused: a newer/corrupt save still occupies the live path and could not be preserved; not clobbering it.", {})`. Fired (once per store) when a newer/corrupt save EXISTS but its preserve rename failed, so the file is still at `SAVE_PATH`; the store refuses every subsequent write rather than rename a fresh save over the un-preserved file. The in-memory game keeps running and persistence resumes on the next launch once a fresh store preserves the file; in this case the `.newer.bak`/`.corrupt.bak` refusal warning above carries `preserved_path=""`.
- Empty fishing pool — `trace.warning("FishingRuntime", "Fishing pool was empty after the viability filter; the cast yielded nothing.", {rod_id, tier})`. Fired when a bite rolled but EVERY species in the tier pool failed the catalog viability gate (sprites/catch rate/learnset) — the cast then refuses `no_species` (`fishing_refused`). Watch for it after touching `scripts/data/` or the tier pools in `scripts/domain/fishing.gd`.
- Egg species missing — `trace.warning("BreedingRuntime", "Egg species missing from the catalog; hatch skipped.", {species_id})`. Fired when a party egg's pre-computed species no longer resolves in the live catalog at hatch time (catalog drift); the egg stays un-hatched rather than hatching into garbage. The `egg/` catalog entry itself is sprite-only and never hatched (the REAL species entry is used).
- Pen lost — `trace.warning("BreedingRuntime", "A pen no longer encloses; mons relocated to the campsite.", {pen, mons_relocated, eggs_lost})`. Fired from `breeding_runtime.apply_save_state` when a pen's enclosure no longer floods — on load OR LIVE the moment fences are built/demolished (`note_structures_changed` runs the same pass immediately, so a broken ring never strands its mons until the next load): its mons return to the campsite hold (`campsite_pokemon`, the capture-relocation never-lose precedent — NO mon is ever lost to a demolished pen) and its ground eggs are lost; the pasture entry is erased and the change persisted.
- Stone bad target — `trace.warning("GameRuntime", "Evolution stone target species is missing from the catalog.", {item_id, target_id})`. Fired from `stone_evolution_runtime.use_stone_on_mon` when `check_item_evolution` resolves a target the live catalog no longer carries (catalog drift); the use refuses `bad_target`, consumes nothing, and the mon is unchanged.
- Pen not breedable — `trace.warning("BreedingRuntime", "Pen holds Pokemon that cannot breed.", {reason: "not_breedable", pen})`. Fired ONCE per pen (until the geometry changes) when a lay cadence finds mons but no `Breeding.find_pair` pair can form among them (genderless without Ditto, disjoint egg groups, a third compatible mon breaking attraction).
- Pasture action refused — `trace.warning("HabitatRuntime", "Pasture action refused.", {action, reason, species_id})`. Fired on every `habitat_runtime` deposit/withdraw refusal (`no_such_mon` / `egg_guard` / `last_party_member` / `not_in_pen` / `party_full`); the alongside `pasture_refused` event carries the player-facing payload.
- Fishing refused — `trace.warning("FishingRuntime", "Fishing refused.", {rod_id, reason})`. Fired on every `fishing_runtime.try_fish` refusal (`no_rod` / `no_water` / `no_species`); consumes no rng, mirrored by the `fishing_refused` event.
- Overworld pool fallback — `trace.warning("OverworldMonsRuntime", "Overworld pool fell back to the full catalog.", {biome, time})`. Fired when `biome_encounters.filter_species_ids` yields nothing for a cell-center biome/time pair and the spawn pool falls back to the full catalog (catalog/biome-table drift); the slot still spawns, off the fallback pool. Watch for it after touching `scripts/domain/biome_encounters.gd` or `scripts/data/`.
- Entity species missing — `trace.warning("OverworldMonsRuntime", "Entity species missing from the catalog; cannot build an instance.", {species_id})`. Fired from `_stamp_instance` when a live entity's species no longer resolves in the catalog at instance-build time (catalog drift); that Attack/recruit/guardian-battle attempt refuses `no_species` and builds nothing rather than a garbage instance.
- Overworld sprite missing — `trace.warning("EntityLayer", "Overworld sprite missing for <species_id>; using the placeholder.", {species_id})`. Fired ONCE per species when a spawned species lacks an overworld sheet under `pokewilds/pokemon/` (asset-coverage gap — 281/990 species); the render falls back to the source game's own `overworld_not_found.png` placeholder, never a blank sprite. Loud and named, never silent-passed.
